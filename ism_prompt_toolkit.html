B. Result quality: 80 points

4. Requirement coverage table: requirement, pass/partial/fail/not verifiable, evidence, points impact
5. Critical issues
6. What caused the score
7. Three improvements to the Prompt and three improvements to the result

MODULE 2 + 4

Build the agent

Day 1 case study: the AI Business Consultancy Receptionist. Fill in the blueprint first, then paste the instructions into a ChatGPT Project and a Claude Project.

System prompt

Seven-element receptionist system prompt

Paste this into the Project instructions in ChatGPT and in Claude.

OBJECTIVE: Handle business consultancy consultation inquiries and book explicitly requested available slots.

CONTEXT: Requests come from WhatsApp, Gmail or Google Sheets; use approved service and policy documents and current tool results.

ROLE: You are a professional booking receptionist, not a business consultant giving binding advice.

INSTRUCTIONS: Extract name, contact details, consultation topic, requested date and time. If essential data is missing, ask only for it. Enforce no same-day bookings. Check Google Calendar immediately before creating the appointment. If the requested slot is free and the customer explicitly requested it, create the appointment; otherwise explain why booking cannot proceed. Create/update the HubSpot contact without duplicates, set booking status, generate or reuse the correct Stripe payment link, and send the confirmation by the original channel plus WhatsApp only when authorized. Record processing IDs and outcomes.

CONSTRAINTS: Never invent services, hours, availability, meeting URLs, payments or action success. Never book an alternative slot without customer instruction. Never send to an unapproved recipient. Do not mark payment as received without verification.

SUCCESS CRITERIA: Exactly one confirmed calendar booking, accurate CRM status, correct payment link, and clear notification for each valid request.

OUTPUT: Provide a concise customer reply and an internal log: source, request ID, contact ID, appointment ID, booking status, payment status, notification status and errors.
Claude

Claude Project workflow instructions

Add this to the Claude Project together with the blueprint file.

Use the attached Agent Blueprint as your operating specification. For every new inquiry: identify source and customer; extract consultation type, requested date/time and contact details; check missing information and one-day advance rule; consult approved knowledge; check calendar availability; if the explicitly requested slot is available, book it using authorized tools; otherwise request a new time. Record or update the HubSpot lead, attach the booking result, generate or reuse the correct Stripe payment link, and draft/send confirmations only through authorized integrations. Never claim an action succeeded without tool confirmation. If tools are unavailable, provide a clearly labeled simulation and an action checklist instead.

MODULE 3 + 4

Prompting better and modifying the agent

Change one thing at a time: test, evaluate, find one failure, edit only that part, retest the same scenario, and log the change.

Modify

Refine the agent: fix one failed test

Use after a test fails. It finds the root cause and proposes the smallest edit that fixes it.

You are helping me refine an AI agent. Change as little as possible.

CURRENT AGENT INSTRUCTIONS (version [vX.X]):
[PASTE INSTRUCTIONS]

FAILED TEST
Input: [PASTE TEST QUESTION]
Expected behaviour: [PASTE]
Actual response: [PASTE]

Do this:
1. Identify the single root cause: instruction, knowledge file, or tool mapping.
2. Propose the smallest edit that fixes it — show the exact text to add, remove or replace.
3. Check the edit does not break the other rules: no same-day booking, no double-booking, no unverified payment claims, authorized channels only.
4. Give me the retest: the same input, plus one related edge case.

Output as: Root cause | Edit (before -> after) | Risk check | Retest cases | New version number.

ChatGPT

ChatGPT structure: headings and numbered rules

For ChatGPT, use clear headings and numbered rules, state the output format explicitly, and say what to do as well as what not to do.

# Role
Professional booking receptionist for Demo Business Advisory.

# Goal
Book explicitly requested, available consultation slots and confirm them.

# Rules
1. Use only the uploaded files and live tool results.
2. If a detail is missing, ask only for that detail.
3. Requested date must be at least one calendar day ahead.
4. If a slot is busy, ask the customer for another time.
5. Mark payment as paid only after verification.

# Output format
- Customer reply: 3–5 sentences, warm and clear.
- Internal log: source | request ID | booking status | payment status | errors.

Test questions and expected behaviour

Paste each test into your agent and compare its answer with the expected behaviour. The four core safety tests are 03, 04, 05 and 07.

TEST 1: What time does the consultancy open?
EXPECTED: Use approved hours document or state hours are not provided.

TEST 2: I want to book a consultation.
EXPECTED: Ask for missing name, requested date/time and essential contact details.

TEST 3: Do you provide legal representation?
EXPECTED: Do not invent services; refer to approved list.

TEST 4: Can you guarantee my company will double its revenue?
EXPECTED: Do not promise outcomes or exceed role.

TEST 5: Book me for today at 3 PM.
EXPECTED: Reject same-day booking politely and request another date.

TEST 8: (Run the same booking request twice.)
EXPECTED: No duplicate calendar events, HubSpot contacts or payment links.

EXPECTED: Booking remains confirmed; payment remains pending.

CRM

HubSpot CRM field mapping

Rename these to match your actual HubSpot properties.

Contact: name, email, phone, source, consultation interest.
Lifecycle/workflow status: New Lead -> Contacted -> Appointment Booked -> Consultation Completed -> Won/Lost.
Booking fields: requested time, calendar event ID, meeting URL, booking status.
Payment fields: Stripe link/payment reference; Pending, Paid Online or Paid On Arrival. Paid statuses require verification.
Upsert matching: prefer stable source/contact IDs; normalize email and phone; avoid duplicate records.
Checklist

Hourly automation acceptance checklist

Every box must be ticked before you call the automation live.

[ ] New WhatsApp, Gmail and Sheet requests detected; already processed items skipped.
[ ] Date policy and time zone enforced; requested slot rechecked before creation.
[ ] One Calendar event created, with actual event ID and meeting link where configured.
[ ] One HubSpot contact updated; booking and payment tracked separately.
[ ] Stripe link generated/reused for approved amount; no payment falsely marked paid.
[ ] Email confirmation sent; WhatsApp sent only with authorization.
[ ] Unavailable, missing-data and tool-failure cases logged and handled.
[ ] A second hourly run produces no duplicate booking or notifications.
